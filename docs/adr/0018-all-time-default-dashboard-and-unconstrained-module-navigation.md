# ADR 0018: All-Time Default Dashboard and Unconstrained Module Navigation

## สถานะ
ยอมรับ (Accepted) — 2026-10-05

## บริบทและปัญหา (Context)
เมื่อผู้ใช้งานเข้าใช้งานระบบบน Production Server (`https://servicehub.behn.go.th`):
- ผู้ใช้สังเกตว่าในเครื่องทดสอบ XAMPP หน้าแดชบอร์ดมีตัวเลขแสดงผลครบทั้ง 9 หมวดงาน (รวม 26 รายการในเดือนนี้) แต่บนเซิร์ฟเวอร์ ข้อมูลจริงที่ผู้ใช้เพิ่งบันทึกไป เช่น *สุเหร่าวัดปากน้ำ* ในหมวดการล้างทำความสะอาดถนนฯ กลับไม่แสดงตัวเลขขึ้นบนการ์ดแดชบอร์ด (ขึ้นเป็น 0 รายการ)
- เมื่อคลิกเข้าไปที่การ์ดหมวดงาน ระบบนำทางด้วย URL ที่มีพารามิเตอร์ช่วงวันที่ของเดือนปัจจุบัน (`?from=...&to=...`) ส่งผลให้หน้ารายการแสดงผลเป็นสถานะว่างเปล่า ("ไม่พบรายการข้อมูล")
- ผู้ใช้ตั้งข้อสงสัยว่าระบบแดชบอร์ดบนเซิร์ฟเวอร์ไม่ได้ดึงข้อมูลจริงมาแสดงเหมือนใน XAMPP หรือเกิดความผิดพลาดในการเชื่อมโยงข้อมูล

### การวินิจฉัยเชิงลึก (Root Cause Diagnosis)
1. **การบังคับใช้ตัวกรองช่วงเดือนปัจจุบันเป็นค่าเริ่มต้น (Enforced Current-Month Default):**
   - แดชบอร์ดเดิมกำหนดให้คำนวณและแสดงผลเฉพาะงานบริการที่ `service_date` อยู่ระหว่างวันที่ 1 ถึงวันสิ้นสุดของเดือนปัจจุบัน (`startOfMonth` ถึง `endOfMonth`)
   - ในเครื่อง Local XAMPP มีการรัน `SampleDataSeeder` ซึ่งสร้างข้อมูลจำลอง 103 รายการ โดยมี 26 รายการตกอยู่ในเดือนตุลาคม 2569 จึงทำให้เห็นตัวเลขเต็มทุกการ์ด
   - บน Production Server ซึ่งเป็นฐานข้อมูลจริงที่เพิ่งเริ่มต้นใช้งาน รายการที่ผู้ใช้บันทึกจริงอาจมีวันที่ดำเนินงาน (`service_date`) อยู่นอกช่วงเดือนปัจจุบัน (เช่น งานปลายเดือนกันยายน หรือการบันทึกงานย้อนหลัง) ส่งผลให้ตัวเลขในการ์ดถูกกรองออกเหลือ 0 รายการ
2. **การส่งต่อตัวกรองแบบมีเงื่อนไขผูกติด (Constrained Navigation Propagation):**
   - ลิงก์บนการ์ดหมวดงานบริการส่งพารามิเตอร์ `?from=...&to=...` ไปยังหน้ารายการเสมอ แม้ผู้ใช้ไม่ได้เป็นผู้เลือกช่วงเวลาเอง ทำให้ผู้ใช้มองไม่เห็นรายการงานจริงที่ถูกบันทึกไว้นอกช่วงเดือนปัจจุบัน
3. **ผลลัพธ์จากการทำ Grilling ร่วมกับผู้ใช้งาน:**
   - ผู้ใช้ระบุเจตนารมณ์ชัดเจนว่า **ไม่ต้องการนำเข้าข้อมูลจำลองจาก XAMPP** ขึ้นเซิร์ฟเวอร์จริง
   - ผู้ใช้ต้องการให้แดชบอร์ดดึงเฉพาะรายการที่บันทึกจริงบนเซิร์ฟเวอร์มาแสดง โดยปรับค่าเริ่มต้นของแดชบอร์ดเป็น **"ทั้งหมดทุกช่วงเวลา" (All Time)** เพื่อให้เห็นยอดสะสมของข้อมูลจริงทั้งหมดทันที

## การตัดสินใจ (Decision)

### 1. ปรับปรุง API แดชบอร์ดให้รองรับโหมด "ทั้งหมดทุกช่วงเวลา" (`GET /api/dashboard`)
- ไฟล์: [`app/Http/Controllers/Api/ServiceOverviewController.php`](file:///c:/xampp/htdocs/Servicehub/app/Http/Controllers/Api/ServiceOverviewController.php)
- เมื่อคำขอไม่มีการส่งพารามิเตอร์ `from` และ `to`:
  - ไม่ใส่เงื่อนไข `whereBetween('service_date', ...)` ในการรวมยอด
  - คืนค่า `data.period.from = null` และ `data.period.to = null`
  - ยอดสะสมใน `period.total`, `module_summary[id].count`, และตัวชี้วัดปริมาณ (`metrics`) จะคำนวณจากทุกรายการจริงในฐานข้อมูลที่ยังไม่ถูกลบ (`deleted_at IS NULL`)
  - แผนภูมิแนวโน้ม (`data.trend`) สรุปผลย้อนหลัง 6 เดือนล่าสุดอย่างปลอดภัย
- หากคำขอมีการระบุ `from` และ `to`: ระบบยังคงกรองข้อมูลตามช่วงเวลาที่กำหนดอย่างแม่นยำเช่นเดิม

### 2. ปรับปรุงส่วนควบคุมตัวกรองและปุ่มลัดช่วงเวลาด่วน (Quick Presets)
- ไฟล์: [`src/utils/filter.js`](file:///c:/xampp/htdocs/Servicehub/src/utils/filter.js)
  - เพิ่มปุ่มชิปพรีเซ็ต **"ทั้งหมด"** (`preset='all'`) โดยกำหนดค่า `{ from: '', to: '' }`
  - มีสถานะ `aria-pressed="true"` เมื่อไม่มีการเลือกช่วงวันที่
- ไฟล์: [`src/dashboard.js`](file:///c:/xampp/htdocs/Servicehub/src/dashboard.js)
  - ช่องกรองวันที่ `<input type="date" name="from">` และ `name="to"` เริ่มต้นเป็นค่าว่าง
  - ปรับหัวข้อย่อยตามสถานะ:
    - *โหมดทั้งหมด:* `ข้อมูลสะสมทั้งหมดตั้งแต่เริ่มระบบ (เฉพาะหมวดที่คุณมีสิทธิ์ดู)`
    - *โหมดกรอง:* `ช่วงวันที่ดำเนินงาน: [from] – [to]`
  - มีปุ่มทางลัด "ดูทั้งหมด" สำหรับคืนค่าสู่โหมดทั้งหมดได้ในคลิกเดียว

### 3. การนำทางข้ามไปยังหมวดงานบริการโดยไม่จำกัดช่วงเวลา (Unconstrained Module Navigation)
- ไฟล์: [`src/dashboard.js`](file:///c:/xampp/htdocs/Servicehub/src/dashboard.js)
- เมื่อแดชบอร์ดอยู่ในโหมดค่าเริ่มต้น (ทั้งหมดทุกช่วงเวลา):
  - ลิงก์บนการ์ดหมวดงานจะชี้ตรงไปยัง `#/module/{id}` ทันที โดยไม่ส่งพารามิเตอร์วันที่
  - ผู้ใช้คลิกเข้าสู่หมวดงานแล้วจะพบรายการจริงทั้งหมดในฐานข้อมูลทันที ไม่เกิดปัญหาหน้าว่างเปล่า
- เมื่อแดชบอร์ดอยู่ในโหมดกรองวันที่ (ผู้ใช้เจาะจงเลือกช่วงเวลาเอง):
  - ลิงก์บนการ์ดหมวดงานจะส่ง `?from=...&to=...` ตามที่ผู้ใช้กำหนดไว้

## ผลลัพธ์ (Consequences)
- **สอดคล้องกับพฤติกรรมจริงของผู้ใช้:** ทุกรายการจริงที่บันทึกบนเซิร์ฟเวอร์จะปรากฏบนการ์ดแดชบอร์ดทันที ไม่สูญหายจากข้อจำกัดของรอยต่อเดือน
- **ขจัดปัญหาหน้าว่างเปล่าเมื่อคลิกจากการ์ด:** ผู้ใช้สามารถคลิกดูรายการที่บันทึกไว้ได้ทันที
- **รักษาความสะอาดของฐานข้อมูล:** ไม่มีการปนเปื้อนข้อมูลตัวอย่าง (Mock Data) ลงในฐานข้อมูล Production
- **ผ่านการทดสอบอัตโนมัติ 100%:**
  - Automated PHPUnit Tests ผ่านครบ 180/180 รายการ (1,978 assertions)
  - Frontend Node Tests ผ่านครบ 14/14 รายการ
  - Laravel Pint Code Style สะอาด 100%
  - Vite Production Assets คอมไพล์สำเร็จ
