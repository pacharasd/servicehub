# ADR 0017: Contextual Empty State and Active Filter Banner in Activity Modules

## สถานะ
ยอมรับ (Accepted) — 2026-10-05

## บริบทและปัญหา (Context)
หลังจากการปรับระบบ On-Demand Module Fetching (ADR 0015) และการแก้ไขสิทธิ์ Super-Admin (ADR 0016) ผู้ใช้รายงานว่าเมื่อเข้าสู่ระบบบน Production Server:
- ในหน้าแดชบอร์ด กล่อง "บันทึกล่าสุด" มีรายการงาน เช่น *สุเหร่าวัดปากน้ำ* แต่เมื่อคลิกเข้าไปในหมวดงานบริการ "การล้างทำความสะอาดถนน ลดฝุ่น และพัฒนาเขตรักษาความสะอาด" (`#/module/road-washings`) หน้าจอกลับแสดง:
  > **"ไม่พบรายการข้อมูล: ลองเปลี่ยนคำค้นหาหรือช่วงวันที่ แล้วค้นหาอีกครั้ง"**
- ส่งผลให้ผู้ใช้สับสนและเข้าใจว่าข้อมูลสูญหาย หรือระบบทำงานผิดพลาด

### การวินิจฉัยเชิงลึก (Root Cause Diagnosis)
1. **การกรองช่วงเวลาเริ่มต้นจากแดชบอร์ด (Dashboard Date Filter Propagation):**
   - แดชบอร์ดตั้งค่าช่วงเวลาเริ่มต้นเป็นเดือนปัจจุบัน (เช่น ตุลาคม 2569: `from=2026-10-01&to=2026-10-31`)
   - เมื่อผู้ใช้คลิกการ์ดหมวดงานจากแดชบอร์ด ลิงก์จะส่งพารามิเตอร์ `?from=...&to=...` ไปยังหน้ารายการของหมวดนั้น ๆ
   - ข้อมูลในฐานข้อมูลจริงบนเซิร์ฟเวอร์ (เช่น รายการ *สุเหร่าวัดปากน้ำ*) ได้รับการบันทึกด้วยวันที่ดำเนินงาน (`service_date`) ในอดีต (เช่น เดือนกันยายน 2569) ทำให้ผลลัพธ์ของช่วงเดือนตุลาคมมี 0 รายการ
2. **ความสับสนจากวันที่ดำเนินงาน vs วันที่บันทึกระบบ (Service Date vs Record Creation Timestamp):**
   - กล่อง "บันทึกล่าสุด" บนแดชบอร์ดดึง 5 รายการล่าสุดจากระบบโดยไม่จำกัดช่วงวันที่ โดยแสดงวันที่ `created_at` (วันที่ผู้ใช้กดบันทึกในระบบ) แต่ตัดทอนข้อความจนเข้าใจผิดคิดว่าเป็นวันที่ปฏิบัติงานจริง
3. **สถานะว่างเปล่าขาดบริบท (Lack of Contextual Empty State & Filter Visibility):**
   - หน้ารายการเมื่อไม่พบข้อมูล (0 รายการ) ไม่ได้ระบุชัดเจนว่าติดเงื่อนไขตัวกรองช่วงวันที่ใดอยู่
   - ปุ่มล้างตัวกรองอยู่ในแบบฟอร์มด้านบนซึ่งอาจตกขอบจอ และไม่มีปุ่มด่วนสำหรับ "แสดงข้อมูลทั้งหมดทุกช่วงเวลา"
4. **ความเสี่ยงจากการไม่ระบุวันที่ตอนสร้างรายการใหม่ (Form Service Date Defaulting):**
   - แบบฟอร์มเพิ่มรายการใหม่ไม่ได้ระบุวันที่เริ่มต้น ทำให้ผู้ใช้อาจเผลอบันทึกรายการโดยใส่วันที่ไม่ตรงกับวันที่ปฏิบัติงานจริง

## การตัดสินใจ (Decision)

### 1. เพิ่มแถบแจ้งเตือนสถานะตัวกรอง (Active Filter Banner)
- เพิ่มแถบแจ้งเตือนบริเวณเหนือตารางข้อมูลเมื่อมีการใช้ตัวกรอง (`from`, `to`, `q`, หรือการอ้างอิงหมวดหมู่)
- ระบุข้อความสรุปเงื่อนไขตัวกรองอย่างชัดเจน เช่น `"กำลังกรองข้อมูล: ช่วงวันที่ 1 ต.ค. 2569 – 31 ต.ค. 2569 (ไม่พบรายการ)"`
- มีปุ่มทางลัดขนาดใหญ่ เด่นชัด: `"แสดงข้อมูลทั้งหมดทุกช่วงเวลา"` ที่คลิกแล้วจะรีเซ็ตตัวกรองช่วงเวลาทันที (`href="#/module/{id}"`)

### 2. ยกระดับสถานะว่างเปล่าตามบริบทตัวกรอง (Contextual Empty State)
- ปรับปรุง Empty State ให้แยกแยะระหว่าง:
  - **กรณีมีตัวกรองแต่ไม่พบข้อมูล:** แสดงไอคอนแจ้งเตือนสีส้มอ่อน หัวข้อ `"ไม่พบรายการข้อมูลตามเงื่อนไขที่เลือก"` อธิบายอย่างชัดเจนว่า `"ไม่มีการบันทึกงานบริการ... ระหว่างวันที่ [from] ถึง [to] คุณสามารถคลิกปุ่มด้านล่างเพื่อดูข้อมูลทั้งหมดในอดีต หรือเลือกช่วงเวลาอื่น"` พร้อมปุ่มหลัก `"แสดงข้อมูลทั้งหมดทุกช่วงเวลา"` และปุ่มรอง `"+ เพิ่มข้อมูลใหม่"`
  - **กรณีไม่มีตัวกรองและยังไม่มีข้อมูลเลย:** แสดงข้อความ `"ยังไม่มีข้อมูลในหมวดนี้"` พร้อมปุ่มเชิญชวนให้เริ่มต้นบันทึกข้อมูล

### 3. แยกการแสดงผลวันที่ดำเนินงานและวันที่บันทึกในแดชบอร์ด
- ปรับแถว "บันทึกล่าสุด" ใน `src/dashboard.js` ให้แสดงข้อความแยกบรรทัดชัดเจน:
  - `วันที่ดำเนินงาน: [service_date]` แบบไม่ตัดทอน
  - `บันทึกเมื่อ: [created_at]`
  - ช่วยให้ผู้ใช้เข้าใจทันทีว่างานนี้ดำเนินงานในวันใด และบันทึกลงระบบเมื่อใด

### 4. กำหนดวันที่ดำเนินงานเริ่มต้นเป็นวันปัจจุบันในแบบฟอร์ม (Form Date Default)
- ใน `formPage` ของ `src/views/activities.js` กำหนดค่าเริ่มต้นของ `service_date` สำหรับรายการใหม่เป็นวันปัจจุบันในรูปแบบ ISO Local Date (`YYYY-MM-DD`) ป้องกันการหลงลืมหรือบันทึกผิดพลาด

## ผลลัพธ์ (Consequences)
- **ขจัดความเข้าใจผิดของผู้ใช้:** ผู้ใช้ทราบทันทีว่าเหตุใดข้อมูลจึงไม่แสดง และสามารถกดปุ่ม "แสดงข้อมูลทั้งหมดทุกช่วงเวลา" เพื่อดูข้อมูลในอดีตได้ด้วยคลิกเดียว
- **UX สอดคล้องกับมาตรฐานสากล (WCAG 2.2 Level AA & Nielsen Norman Group guidelines):** มี Feedback ที่ชัดเจน ไม่ปล่อยให้ผู้ใช้ติดอยู่ใน Dead-end State

  - PHPUnit ครอบคลุม 179 รายการ (100% Pass)
  - Laravel Pint Code Style ผ่านการตรวจสอบ
