# 6. รวมปุ่มโปรไฟล์ผู้ใช้และปุ่มออกจากระบบเป็น User Dropdown Menu บน Topbar

**สถานะ:** กำลังดำเนินการ (Proposed / Under Review)  
**วันที่:** 2026-09-30  
**การตัดสินใจร่วมกับ:** ผู้ใช้งานระบบ ServiceHub ผ่านกระบวนการ `/grill-with-docs`

---

## 1. บริบทและปัญหา (Context)

ในส่วนหัวแถบนำทางด้านบน (Topbar Header) ของแอปพลิเคชัน ServiceHub เดิมมีปุ่มแยก 2 ปุ่มวางคู่กันทางด้านขวา:
1. ปุ่มแสดงชื่อผู้ใช้และอวาตาร์ (`[อักษรย่อ] ชื่อผู้ใช้งาน`) สำหรับคลิกไปยังหน้าโปรไฟล์ `#/profile`
2. ปุ่มออกจากระบบ (`[ไอคอน] ออกจากระบบ`) สำหรับส่งแบบฟอร์ม Logout ออกจากระบบทันที

ปัญหาที่พบคือ:
- การวางปุ่มออกจากระบบแบบเปิดเผยคู่กับโปรไฟล์ทำให้ Header ดูแน่นและรก โดยเฉพาะบนหน้าจอขนาดเล็ก (Mobile / Tablet)
- มาตรฐานสากลของ Enterprise Web Application (เช่น Google Workspace, GitHub, Microsoft 365) นิยมรวมการจัดการข้อมูลตัวตน (Identity) เข้าไว้ด้วยกันเป็นปุ่มเดียวในรูปแบบ **User Menu Dropdown**

---

## 2. การตัดสินใจทางสถาปัตยกรรม (Decisions)

### 2.1 รูปแบบการทำงานและปฏิสัมพันธ์ (Interaction & Visual Pattern)
- รวมปุ่มโปรไฟล์และปุ่มออกจากระบบเป็นปุ่ม **User Dropdown Menu** ปุ่มเดียวบน Topbar
- **ลักษณะปุ่มบน Topbar:**
  - แสดง Avatar อักษรย่อของผู้ใช้
  - แสดงชื่อผู้ใช้ (ตัดข้อความหรือซ่อนบนมือถือเพื่อให้พอดีพื้นที่)
  - แสดงไอคอน Chevron Down เพื่อระบุอย่างชัดเจนว่าเป็นเมนูกางลงมาได้
- **ลักษณะเมื่อคลิกเปิด (Dropdown Popover):**
  - **ส่วนหัว (Header Card):** แสดง Avatar, ชื่อ-นามสกุลเต็ม, `@username`, และป้ายบทบาท (Role Badge)
  - **เมนูที่ 1:** ลิงก์ไปยัง `#/profile` ("โปรไฟล์ของฉัน") พร้อมไอคอนผู้ใช้
  - **เส้นคั่น (Divider):** แบ่งส่วนระหว่างการจัดการบัญชีกับการออกจากระบบ
  - **เมนูที่ 2:** ปุ่ม "ออกจากระบบ" (สีแดง/เน้นชัดเจน) พร้อมไอคอน Logout
- **พฤติกรรมการออกจากระบบ:** กดปุ่ม "ออกจากระบบ" แล้วทำการส่งฟอร์ม Logout ทันทีโดยไม่ต้องผ่าน Modal ยืนยันซ้ำซ้อน เพื่อความรวดเร็วและตรงตามพฤติกรรมเดิมที่ผู้ใช้คุ้นเคย

### 2.2 การเข้าถึงและเมนูด้านข้าง (Sidebar Coexistence)
- ยังคงเมนู "โปรไฟล์ของฉัน" ในเมนูด้านข้าง (Sidebar) ไว้ตามเดิม เพื่อให้ผู้ใช้งานที่สะดวกนำทางผ่านเมนูหลักสามารถเข้าถึงหน้าโปรไฟล์ได้โดยตรง

### 2.3 การรองรับการเข้าถึงและขนาดหน้าจอ (Accessibility & Responsiveness)
- **Keyboard & Focus:**
  - กำหนด `aria-haspopup="menu"`, `aria-expanded` เพื่อรองรับ Screen Reader
  - รองรับการกดปุ่ม `Escape` เพื่อปิดเมนูและคืน Focus ให้ปุ่มเปิด
  - ปิดเมนูอัตโนมัติเมื่อคลิกพื้นที่อื่นภายนอก (Click outside) หรือเมื่อคลิกลิงก์เปลี่ยนหน้า
- **Responsive Layout:**
  - กำหนดการจัดวางให้อยู่ชิดขวาของ Topbar (`right-0 mt-2`)
  - มีการจำกัดความกว้างสูงสุดและเว้นระยะปลอดภัย ไม่ให้ล้นจอในหน้าจอขนาดเล็กที่สุด (320px)

## 3. ผลกระทบและการตรวจรับ (Consequences & Verification)

- **ความเรียบร้อยของหน้าจอ:** Topbar มีความสะอาด คลีน สวยงาม ทันสมัย และสอดคล้องกับมาตรฐาน Enterprise UI
- **Zero Horizontal Overflow:** ไม่มีแถบเลื่อนแนวนอนในทุกขนาดหน้าจอ
- **Automated Verification:**
  - โค้ดผ่านการจัดรูปแบบด้วย Laravel Pint
  - ผ่านการ Build Production ด้วย Vite
  - Feature Tests ทั้งหมดยังคงผ่าน 100%
