# ADR 0010: ระบบตัวกรองสากลและการซิงก์สถานะผ่าน URL (Universal Filtering and URL State Synchronization)

## สถานะ (Status)
ยอมรับแล้ว (Accepted) — 2026-10-02

## บริบท (Context)
ในระบบเดิม หน้าจอต่างๆ มีการจัดการตัวกรองที่ไม่เป็นรูปแบบเดียวกัน:
- หน้าผู้ใช้งาน (`users.js`) มีระบบ Live Debounce Search และ Dropdown Filter แต่หน้าอื่นๆ เช่น งานบริการ 9 หมวด และ ข้อมูลหลัก ยังต้องกดปุ่มค้นหาแบบเดิม
- หน้าประวัติการแก้ไข (`auditLogs.js`) มีเพียงช่องค้นหาข้อความ และไม่มีตัวจัดการ Submit ใน `main.js` ทำให้การกดค้นหามีปัญหา
- หน้าแดชบอร์ด (`dashboard.js`) และรายงาน (`reports.js`) มีเฉพาะการเลือกวันที่เริ่มต้น/สิ้นสุด แต่ขาดปุ่มลัดช่วงเวลาด่วน (Quick Presets) เช่น "วันนี้", "7 วันล่าสุด", "เดือนนี้" ซึ่งเป็นรูปแบบการใช้งานหลักของเจ้าหน้าที่ฝ่ายบริการ
- สถานะตัวกรองในบางหน้าไม่ได้ซิงก์กลับเป็น URL Query String ทำให้ผู้ใช้ไม่สามารถกด Back/Forward หรือแชร์ลิงก์ค้นหาได้

## การตัดสินใจ (Decision)
เราตัดสินใจออกแบบและใช้งาน **ระบบตัวกรองสากล (Universal Filter Architecture)** ทั่วทั้งระบบ โดยมีหลักการดังนี้:

1. **พฤติกรรมการกรองแบบ Live / Debounced:**
   - ช่องค้นหาข้อความ (`q`) มี Debounce หน่วงเวลา 300ms ก่อนเริ่มค้นหาอัตโนมัติ
   - Dropdown ตัวกรอง (หมวด, สถานะ, บทบาท, การจัดเรียง) ทริกเกอร์การกรองทันทีเมื่อเปลี่ยนค่า (`change` event)
   - มีปุ่ม **"ล้างตัวกรอง" (Clear Filters)** ที่จะรีเซ็ตค่ากลับสู่ค่าเริ่มต้นทั้งหมดในคลิกเดียว

2. **ปุ่มลัดช่วงเวลาด่วน (Quick Date Presets):**
   - มีชิปปุ่มลัด 4 ช่วงเวลา: `วันนี้ (today)`, `7 วันล่าสุด (7d)`, `เดือนนี้ (month)`, `30 วันล่าสุด (30d)`
   - ใช้งานในหน้าแดชบอร์ด, รายการงานบริการ 9 หมวด, รายงาน และประวัติการแก้ไข

3. **การซิงก์สถานะลง URL (URL Hash Query Synchronization):**
   - ทุกค่าตัวกรองจะสะท้อนลงใน URL Hash parameters (เช่น `#/module/road-washings?q=สะพาน&from=2026-10-01&sort=newest`)
   - รองรับ Browser History (Back / Forward) และการคัดลอก URL ส่งต่อ

4. **การรองรับ Mobile และการเข้าถึง (WCAG 2.2 AA):**
   - บนหน้าจอขนาดเล็ก (<768px) ตัวกรองเสริมจะถูกยุบไว้ใต้ปุ่ม "ตัวกรองเพิ่มเติม" พร้อม `aria-expanded`
   - ทุก Input มี Label ชัดเจน และปุ่มล้างตัวกรองมี Contrast Ratio ถูกต้อง

## ผลที่ตามมา (Consequences)
- **ข้อดี:** ประสบการณ์ใช้งาน (UX) ราบรื่น เป็นมาตรฐานเดียวกันทั้ง 6 หน้าจอ เจ้าหน้าที่ค้นหาข้อมูลได้รวดเร็วขึ้นมาก ไม่ต้องคอยกดปุ่มส่งฟอร์มซ้ำๆ
- **สิ่งที่ต้องระวัง:** การยิงค้นหาอัตโนมัติ (Live filter) อาจส่ง request บ่อยขึ้น ได้รับการแก้ไขโดยใช้ Debounce 300ms ฝั่งไคลเอนต์ และ Query Aggregation / Caching ฝั่งเซิร์ฟเวอร์
