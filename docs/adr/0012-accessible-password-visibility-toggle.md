# ADR 0012: ปุ่มเปิดดูรหัสผ่านที่เข้าถึงได้และการป้องกันการแสดงผลซ้อนทับ (Accessible Password Visibility Toggle & Browser Reveal Suppression)

## สถานะ (Status)
ยอมรับแล้ว (Accepted) — 2026-10-02

## บริบท (Context)
ในหน้าเปลี่ยนรหัสผ่านส่วนตัว (`#/profile`), หน้าต่างจัดการผู้ใช้งาน (`#/users`), และหน้าเข้าสู่ระบบ:
- เบราว์เซอร์บนระบบปฏิบัติการ Windows เช่น Microsoft Edge และ Chromium มีกลไกสร้างปุ่มลูกตาเปิดดูรหัสผ่านอัตโนมัติ (Native Password Reveal Button / `::-ms-reveal`) อยู่ที่ขอบขวาของช่องกรอก `<input type="password">`
- เมื่อแอปพลิเคชันวางปุ่ม "แสดง/ซ่อน" (Toggle button) ของตนเองไว้ที่มุมขวาของช่องกรอกด้วยเช่นกัน ทำให้เกิดอาการ **ปุ่มซ้อนทับกัน (Overlapping elements)** ส่งผลให้ผู้ใช้มองเห็นปุ่มสองชั้น และกดคลิกลำบาก
- ปุ่มเดิมใช้เป็นข้อความภาษาไทย "แสดง" และ "ซ่อน" ซึ่งมีความกว้างไม่คงที่ และไม่ได้กำกับแอตทริบิวต์การเข้าถึงสำหรับโปรแกรมอ่านหน้าจอ (Screen Reader) ตามเกณฑ์ WCAG 2.2 Level AA

## การตัดสินใจ (Decision)
เราตัดสินใจแก้ไขปัญหาการซ้อนทับและยกระดับปุ่มเปิดดูรหัสผ่านให้เป็นไปตามมาตรฐานสากลดังนี้:

1. **ระงับปุ่มดั้งเดิมของเบราว์เซอร์ในระดับโกลบอล (Global Browser Reveal Suppression):**
   - เพิ่มคำสั่ง CSS ใน `src/style.css` สำหรับช่อง `input[type="password"]` เพื่อซ่อน `::-ms-reveal` และ `::-ms-clear`:
   ```css
   input[type="password"]::-ms-reveal,
   input[type="password"]::-ms-clear {
     display: none !important;
   }
   ```
   - วิธีนี้ช่วยแก้ปัญหาการซ้อนทับได้อย่างเบ็ดเสร็จในทุกเบราว์เซอร์บนทุกแพลตฟอร์ม

2. **ปรับดีไซน์เป็นไอคอนมาตรฐานสากล (Universal Eye/Eye-Off Icons):**
   - เพิ่ม SVG icons `eye` และ `eyeOff` ลงใน [`src/utils/icons.js`](file:///c:/xampp/htdocs/Servicehub/src/utils/icons.js)
   - สลับแสดงผลระหว่างไอคอนลูกตาเปิด (`eye`) เมื่อรหัสผ่านถูกซ่อนอยู่ และลูกตาขีดฆ่า (`eyeOff`) เมื่อเปิดเผยรหัสผ่าน

3. **มาตรฐานการเข้าถึงและการใช้งาน (WCAG 2.2 AA Standards):**
   - กำหนดขนาด Touch Target เป็น `min-h-11 min-w-11` (อย่างน้อย 44x44px) รองรับการสัมผัสบนมือถือได้อย่างแม่นยำ
   - กำกับ `aria-label="แสดงรหัสผ่าน"` / `aria-label="ซ่อนรหัสผ่าน"` และ `aria-pressed="false"` / `aria-pressed="true"` แบบไดนามิก เพื่อให้โปรแกรมอ่านหน้าจอถ่ายทอดสถานะได้อย่างถูกต้อง
   - ปรับระยะ Padding ด้านขวาของช่อง input เป็น `pr-12` เพื่อไม่ให้ข้อความรหัสผ่านที่กรอกยาวๆ ซ้อนทับใต้ปุ่มไอคอน

4. **ความสอดคล้องทั้งระบบ (System-wide Consistency):**
   - ปรับใช้รูปแบบเดียวกันทั้งในหน้าแก้ไขโปรไฟล์ (`src/views/profile.js`), หน้าต่างเพิ่ม/รีเซ็ตรหัสผู้ใช้ (`src/views/users.js`), และหน้าจอเข้าสู่ระบบ (`resources/views/auth/login.blade.php`)

## ผลที่ตามมา (Consequences)
- **ข้อดี:** แก้ปัญหาปุ่มซ้อนทับหายขาด สวยงาม ดูเป็นมืออาชีพ มีความสม่ำเสมอทั่วทั้งแอปพลิเคชัน และผ่านเกณฑ์การเข้าถึงระดับสากล
- **สิ่งที่ต้องระวัง:** เมื่อเปลี่ยนประเภทอินพุตเป็น `text` หรือ `password` ต้องตรวจสอบว่า Event listener อัปเดตทั้งไอคอน, `aria-label`, และ `aria-pressed` ให้ตรงกันเสมอ
