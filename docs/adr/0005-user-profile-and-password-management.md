# 5. สถาปัตยกรรมระบบโปรไฟล์ผู้ใช้และการจัดการรหัสผ่านตนเอง (User Profile and Self-Service Password Management)

**สถานะ:** อนุมัติแล้ว (Approved)  
**วันที่:** 2026-09-30  
**การตัดสินใจร่วมกับ:** ผู้ใช้งานระบบ ServiceHub ผ่านกระบวนการ `/grill-with-docs`

---

## 1. บริบทและปัญหา (Context)

ระบบ ServiceHub มีระบบยืนยันตัวตน (Authentication) และระบบจัดการผู้ใช้งานระดับองค์กร (User Management) สำหรับผู้ดูแลระบบเรียบร้อยแล้ว แต่ผู้ใช้งานทุกคน (รวมถึง `staff`, `viewer`, `auditor`, `admin`, `super-admin`) ยังไม่มีหน้าจอสำหรับดูข้อมูลบัญชีของตนเอง แก้ไขชื่อที่แสดง (Display Name) หรือเปลี่ยนรหัสผ่านด้วยตนเองได้อย่างปลอดภัย

---

## 2. การตัดสินใจทางสถาปัตยกรรม (Decisions)

### 2.1 ขอบเขตการทำงาน (Scope & Capabilities)
1. **การดูข้อมูลบัญชี (Account Overview):**
   - แสดงชื่อผู้ใช้ (Username - ล็อกไม่ให้แก้ไขตามข้อกำหนดความมั่นคงปลอดภัย)
   - แสดงป้ายบทบาท (Role Badges) และสถานะบัญชี (Active)
   - แสดงวันที่สร้างบัญชี
2. **การแก้ไขชื่อที่แสดง (Display Name):**
   - ผู้ใช้ทุกคนสามารถแก้ไข `name` ของตนเองได้ (ความยาว 1–255 ตัวอักษร รองรับภาษาไทย)
   - เมื่อบันทึกสำเร็จ `window.serviceHubUser.name` จะอัปเดตทันที ทำให้ชื่อบน Topbar และจุดต่าง ๆ ในระบบสะท้อนค่าใหม่อัตโนมัติ
3. **การเปลี่ยนรหัสผ่านของตนเอง (Change Password):**
   - ต้องยืนยัน **รหัสผ่านปัจจุบัน (Current Password)** ถูกต้องก่อนเสมอ
   - รหัสผ่านใหม่ต้องมีความยาวอย่างน้อย 15 ตัวอักษร ตามมาตรฐาน NIST SP 800-63B และ AGENT.md
   - มีระบบสุ่มสร้างรหัสผ่านปลอดภัย (Password Generator) และปุ่มสลับการมองเห็น (Show/Hide Toggle)

### 2.2 ความปลอดภัยและการตัดเซสชัน (Selective Session Invalidation)
- เมื่อผู้ใช้เปลี่ยนรหัสผ่านสำเร็จ:
  - ค่า `auth_version` ของผู้ใช้ในฐานข้อมูลจะถูกเพิ่มขึ้น 1 (`+1`) เพื่อให้เซสชันในอุปกรณ์หรือเบราว์เซอร์อื่นทั้งหมดกลายเป็นโมฆะทันที
  - เซสชันปัจจุบันของผู้ใช้ที่ทำการเปลี่ยนรหัสผ่านจะได้รับการอัปเดต `auth_version` ในเซสชันให้ตรงกับฐานข้อมูล เพื่อให้ผู้ใช้ทำงานต่อเนื่องได้ทันทีโดยไม่ถูกบังคับออกจากระบบ
- การเปลี่ยนแปลงทั้งหมดจะถูกบันทึกลงตาราง `audit_logs` โดยไม่บันทึกรหัสผ่านหรือข้อมูลลับ

### 2.3 การเชื่อมต่อและหน้าจอ UI (Routing & Accessibility)
- **เส้นทาง:** เข้าถึงผ่าน Client Hash Route `#/profile`
- **จุดเข้าถึง (Entry Points):**
  - ปุ่มโปรไฟล์บน Topbar (แสดงอักษรย่อ + ชื่อผู้ใช้)
  - ลิงก์ "โปรไฟล์ของฉัน" ในเมนูด้านข้าง (Sidebar)
- **การออกแบบ UI:** รองรับการแสดงผล Responsive แบบ 2 คอลัมน์บนจอใหญ่ (Desktop) และเรียงการ์ดในแนวตั้งบนจอมือถือ พร้อมรักษาข้อกำหนด Zero Horizontal Overflow บนหน้าจอแคบ 320px
- **Accessibility:** มี Label ชัดเจน, Keyboard focus trap, Aria-invalid เมื่อกรอกข้อมูลไม่ถูกต้อง

---

## 3. ผลกระทบและการตรวจรับ (Consequences & Verification)

- **Positive:** ผู้ใช้ทุกคนสามารถจัดการบัญชีและรหัสผ่านได้ด้วยตนเองอย่างปลอดภัย
- **Security:** ป้องกันการสวมรอยด้วยการบังคับตรวจรหัสผ่านเดิม และตัดเซสชันเครื่องอื่นทันที
- **Quality:** ผ่านการทดสอบ automated test ครบทุกกรณี (ความยาวรหัสผ่าน, รหัสเดิมผิด, selective session invalidation, การบันทึก audit log)
