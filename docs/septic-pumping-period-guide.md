# ช่วงดำเนินงานและผู้ใช้บริการงานสูบสิ่งปฏิกูล

## การกรอกและอ่านข้อมูล

ฟอร์มเรียงวันเริ่ม วันที่สิ้นสุด จำนวนผู้ใช้บริการ ปริมาตรสิ่งปฏิกูลรวม และค่าธรรมเนียม ใช้ปฏิทินไทย พ.ศ. วันเริ่มรายการใหม่เป็นวันนี้ตามเวลาไทย วันสิ้นสุดเลือกเองและต้องไม่ก่อนวันเริ่ม งานวันเดียวเลือกวันที่เดียวกันได้

จำนวนผู้ใช้บริการต้องเป็นจำนวนเต็มตั้งแต่ 1 ถึง 4,294,967,295 คนต่อรายการ เป็นยอดตลอดช่วงดำเนินงาน ไม่ใช่จำนวนรายวัน ระบบไม่เก็บตัวบุคคล จึงอาจนับคนเดิมซ้ำหากรับบริการหลายงาน ไม่นำยอดนี้รวมกับผู้เข้าร่วมโครงการ

ข้อมูลเก่าได้วันสิ้นสุดเท่าวันเริ่ม แต่จำนวนผู้ใช้บริการยังว่าง แสดง “ไม่ระบุ” และต้องกรอกเมื่อบันทึกแก้ไข ไม่สมมติจำนวนเดิมเป็น 0 หรือ 1 ไม่เปลี่ยนปริมาตรหรือค่าธรรมเนียม

แดชบอร์ด รายงาน PDF และไฟล์ส่งออกนับงานและยอดตามวันเริ่มเพียงครั้งเดียว ไม่กระจายตามจำนวนวัน และไม่รวม soft delete ยอดคนรวมเฉพาะงานที่ทราบจำนวน หากยังมีงานไม่ระบุจะแสดง “ยังไม่ระบุจำนวน N รายการ” ถ้าทุกงานไม่ทราบจำนวนแสดง “ยังไม่มีข้อมูลจำนวนผู้ใช้บริการ” ส่วนช่วงที่ไม่มีงานแสดง 0 คน

API งานใช้ URL เดิม เพิ่ม `end_date` และ `service_users_count` ซึ่งบังคับเมื่อเพิ่ม/แก้ไข API แดชบอร์ดและรายงานเพิ่มยอด `metrics.service_users_count` (อาจเป็น null เมื่อทุกงานไม่ทราบจำนวน) พร้อม `service_users_coverage: {recorded, missing}` รายงานคง `quantities` เดิมและเพิ่มตัวชี้วัดจำนวนคนพร้อมหมายเหตุความครบถ้วน CSV รายการดิบเพิ่มชื่อฟิลด์ทั้งสอง Excel แสดงวันที่ พ.ศ. และเก็บจำนวนคนเป็นตัวเลขจริง ส่วนจำนวนเก่าว่างแสดง “ไม่ระบุ”

## นำใช้

1. สำรองฐานข้อมูลและเก็บโค้ด/API/asset รุ่นก่อนหน้า ปิดการบันทึกระหว่างอัปเดต
2. รันเฉพาะ migration ใหม่ด้วย PHP ของเว็บไซต์:

```powershell
php artisan migrate --path=database/migrations/2026_10_19_000002_add_septic_pumping_service_period_and_users.php --force
```

3. อัปเดต API และ `public/dist` รุ่นเดียวกันหลัง `npm run build` ตรวจจำนวนงานเดิม วันสิ้นสุด ปริมาตร ค่าธรรมเนียม และจำนวนคนที่ยังว่าง แล้วทดสอบบันทึกและส่งออกก่อนเปิดให้ใช้งาน
4. หากใช้ phpMyAdmin บนเซิร์ฟเวอร์แทน migration ให้ใช้ไฟล์ `docs/sql/add-septic-pumping-period.sql` หลังสำรองฐาน และอย่ารัน SQL ซ้ำ ไม่มีการเพิ่มสิทธิ์ใหม่ งานนี้ใช้สิทธิ์งานสูบสิ่งปฏิกูลเดิม

Migration รองรับกรณีเพิ่มคอลัมน์ด้วย SQL ไว้ก่อน โดยไม่เติมหรือเขียนทับจำนวนคนหรือวันสิ้นสุดที่มีอยู่ การย้อน migration ลบสองคอลัมน์ใหม่ จึงต้องสำรองข้อมูลใหม่ก่อนย้อนกลับ ห้ามนำชุดทดสอบหรือ sample seeder ไปรันบนฐานใช้งาน

## ถอดสถานที่ออก

สถานที่ไม่แสดงในฟอร์ม ตาราง รายละเอียด API และ CSV/Excel ของงานสูบสิ่งปฏิกูลอีกต่อไป ไม่ใช้เป็นคำค้นหาหรือชื่อกิจกรรมล่าสุด ค้นหาได้จากวันที่มาตรฐาน YYYY-MM-DD กิจกรรมล่าสุดใช้ชื่อ “งานสูบสิ่งปฏิกูล” พร้อมวันที่แยกตามเดิม

คงคอลัมน์ `septic_pumpings.location` และสถานที่เก่าไว้ โดย migration `2026_10_19_000003_make_septic_pumping_location_optional.php` เปลี่ยนเป็น nullable งานใหม่จึงไม่ต้องส่งสถานที่ ไม่ต้องลบคอลัมน์เอง ก่อนนำใช้สำรองฐาน รัน migration นี้ และอัปเดต asset/API พร้อมกัน SQL สำหรับเซิร์ฟเวอร์อยู่ที่ `docs/sql/make-septic-pumping-location-optional.sql`
