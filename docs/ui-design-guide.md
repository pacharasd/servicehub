# คู่มือรูปแบบหน้าจอ ServiceHub

## รูปแบบร่วม

ปัจจุบันใช้ LINE Seed Sans TH WOFF2 น้ำหนักจริง 400/700 เป็นหลัก โดย IBM Plex Sans Thai เป็น fallback ตาม docs/typography-guide.md ไม่มีการเรียก Google Fonts ขณะใช้งาน สีหลัก #0F766E พื้น #F8FAF9 ตัวอักษร #16313A และเส้น #E2E8E7 ใช้ช่องไฟหลัก 8/16/24/32px มุมโค้ง 8–12px และปุ่ม/ช่องกรอกสูงอย่างน้อย 44px

## เมนูและ header

- Desktop ตั้งแต่ 1024px: แถบเมนู 296px ย่อเหลือ 72px จากปุ่มบน header จำสถานะไว้ใน localStorage ชื่อ servicehub.sidebar-collapsed เฉพาะความชอบหน้าจอ ไม่เก็บข้อมูลบริการ หาก storage ถูกปิดยังย่อ/ขยายได้
- เมนูย่อมีชื่อเมื่อ hover/focus กด Escape ปิด tooltip กดไอคอนกลุ่มงานเพื่อขยายเมนูและเปิดกลุ่มนั้น เมนูอื่นใช้ลิงก์เดิม
- Mobile/Tablet ต่ำกว่า 1024px ใช้ drawer เต็มรูปแบบ ไม่ใช้สถานะย่อ desktop เปิดแล้วจำกัด focus ใน drawer และทำเนื้อหาด้านหลัง inert ปิดด้วย Escape หรือ backdrop คืน focus ให้ปุ่มเปิด กดลิงก์แล้วปิด drawer
- กลุ่มเมนูใช้ปุ่ม aria-expanded/aria-controls และเปิดกลุ่มของหน้าปัจจุบัน เมนูผู้ใช้รองรับลูกศรขึ้น/ลง Home End และ Escape
- Header สูง 64px บน desktop และ 56px บนจอเล็ก Breadcrumb ย่อชื่อได้เมื่อพื้นที่จำกัด ส่วนชื่อเต็มยังอยู่ในหัวข้อหน้า

## แดชบอร์ด

ลำดับ: หัวข้อ → ตัวกรอง → KPI → กลุ่มงาน → น้ำหนักมูลฝอยแยกประเภท/สัดส่วน → กิจกรรมล่าสุด → รายหมวด

ตัวกรองใช้ปฏิทิน พ.ศ. และเงื่อนไขเดิม ปุ่มช่วงด่วนแสดงสถานะด้วย aria-pressed และสี มี “ดูทั้งหมด” เมื่อตั้งช่วง วันที่หนึ่งด้านแสดงคำอธิบายให้ตรงกับด้านที่เลือก

กราฟน้ำหนักมูลฝอยแยกตามประเภทขยะใช้ผลรวม SQL จากคิวรีเดียวกับข้อมูลสรุปมูลฝอยใน API แดชบอร์ด (`waste_overview.breakdown`) เรียงน้ำหนักมากไปน้อย หน่วยกิโลกรัม ใช้ช่วงตัวกรองตามวันเริ่ม ไม่รวมรายการที่ลบ แต่รวมประเภทที่ระงับหากมีงานอ้างอิง มีตารางข้อมูลสำหรับโปรแกรมอ่านหน้าจอ ถ้าข้อมูลว่างหรือทุกยอดเป็นศูนย์แสดงข้อความโดยไม่สร้างแท่ง ผู้ไม่มีสิทธิ์ดูงานมูลฝอยจะเห็นเฉพาะกราฟสัดส่วนเต็มพื้นที่ ฟิลด์ trend เดิมใน API ยังคงอยู่เพื่อความเข้ากันได้

สัดส่วนกลุ่มงานคำนวณจากจำนวนรายการรวมของกลุ่มที่มีสิทธิ์ในช่วงเดียวกับตัวกรอง ไม่รวมปริมาณต่างหน่วย ร้อยละปัดหนึ่งตำแหน่งจึงอาจรวมคลาดเคลื่อนเล็กน้อยจาก 100% บันทึกล่าสุดยังเรียงตามเวลาสร้างทุกช่วงเวลา ไม่ใช่รายการแก้ไขล่าสุด

## ไฟล์หลักที่ปรับ

- src/components/navigation.js: เมนู header การย่อ/ขยาย tooltip และคีย์บอร์ด
- src/components/dashboardCharts.js และ src/dashboard.js: กราฟและการจัดองค์ประกอบแดชบอร์ด
- src/style.css และ src/utils/filter.js: design tokens ฟอนต์ layout และขนาดปุ่มช่วงด่วน
- src/main.js: เชื่อม interaction โดยไม่ผูก handler เมนูซ้ำ
- src/utils/icons.js: เส้นไอคอน 2px
- resources/views/app.blade.php และ resources/views/auth/layout.blade.php: ยกเลิกฟอนต์ภายนอก
- tests/frontend/enterpriseUi.test.mjs: ชุดทดสอบ navigation กราฟ และ contrast

## การตรวจและข้อจำกัด

ตรวจ responsive จากโค้ดที่ 320/768/1024/1440px และ JSDOM ทดสอบเมนูย่อ drawer focus trap tooltip dropdown การเปลี่ยนหน้า storage ถูกปิด และ init ซ้ำ ตรวจ contrast สีข้อความหลัก/semantic >=4.5:1 ทดสอบกราฟกับข้อมูลรวมและข้อมูลว่าง ไม่เพิ่มคำขอ API

รัน PHPUnit, JavaScript tests, node --check, Pint และ build รวมถึงตรวจ asset/ฟอนต์ผ่าน HTTP/CLI โดยไม่ใช้เบราว์เซอร์ การตรวจนี้ไม่ใช่การรับรอง WCAG เต็มรูปแบบ ยังต้องยืนยันการจัดวางจริงและโปรแกรมอ่านหน้าจอภายหลัง ไม่เปลี่ยน schema API หรือสิทธิ์จากงาน UX/UI รอบนี้

## การปรับความกระชับเพิ่มเติม

sidebar desktop 296px (ย่อ 72px ตามเดิม) ตัวกรองวางช่องวันที่และปุ่มช่วงด่วนแบบ wrap ร่วมแถวโดยไม่เว้นคอลัมน์ว่างตายตัว รายละเอียดและหน่วยในการ์ดกลุ่มงานใช้ 14px

KPI สามใบแยกเป็นจำนวนรายการในช่วงที่เลือก/สะสมทั้งหมด, จำนวนหมวดที่มีรายการในช่วงเดียวกัน และงานวันนี้ตามเวลาไทย (ไม่ขึ้นกับช่วงที่เลือก) จำนวนหมวดคำนวณจาก module_summary ที่ API ส่งตามสิทธิ์ ไม่ใช่จำนวนหมวดทั้งหมดที่ระบบรองรับ เมื่อกรองช่วงวันที่ ยอดสะสม data.total เดิมอยู่ในคำอธิบายการ์ดแรก จึงไม่แสดงยอดสะสมซ้ำอีกใบ

กิจกรรมล่าสุดย้ายขึ้นก่อนรายหมวด ยังคงเป็นเวลาสร้างทุกช่วงเวลา ไม่ใช่ Audit Log กราฟใช้ข้อมูล API เดิม ไม่เพิ่มคำขอหรือสร้างข้อมูลสมมติ
